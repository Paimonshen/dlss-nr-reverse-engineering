# 内核参数规格

本文给出 `.hip_fat` 元数据内 **34 个内核**的参数与资源规格。这些规格是在 Intel 平台重编内核时的**参照基准**，不是可加载二进制。

## 0. 范围与约定

### 0.1 本文是什么、不是什么

- **本文是「重编参照基准」**：8 条 device bundle 只能用于读取 AMDGPU 侧的参数与资源元数据，作为在 Intel 平台重编内核时的规格输入。
- **本文不描述 host 侧运行时替换**：host 侧（代理导出、thunk、wrapper、handle 表、启动链）见 `03-DLL结构分析.md`。
- **该 fat binary 内不含任何 Intel / Xe / SPIR-V 目标**（9 条 bundle 条目的 triple 全体集合中无 `spirv`、无 `intel`、无 `xe`）。

### 0.2 编号与坐标约定（全文统一）

| 项 | 约定 |
|---|---|
| **bundle 编号** | `entry#0` = host 占位；`device#1..#8` = 8 个 device（`#8` 恒为 `gfx9-generic`） |
| **基准表取自** | `device#1`（`gfx10-3-generic`）—— 8 个 device 的参数面逐项相同（见 §2.2 末注），故单表可代表 8 目标 |
| **VA 换算** | `.hip_fat` 节 VA = `0x18007F000`、RAW = `0x78200` → `file = VA − 0x18007F000 + 0x78200` |
| **msgpack 文档起点** | `bundle + 0x24C` |

`bundle + 0x24C` 的推导：`.note` 节 `sh_offset = +0x238`；note 头 `namesz` @ `+0x238`、`descsz` @ `+0x23C`、`type` @ `+0x240` = **32** = `NT_AMDGPU_METADATA`、name `AMDGPU` @ `+0x244`；故 desc 起点 = `0x238 + 12 + 8 = 0x24C`。

## 1. 参数面

### 1.1 参数条目的字段与语义

`.args` 是每个内核 map 内的参数数组。每个参数是 map，键集合实测两种：

| 键集合 | 次数 |
|---|---|
| `{.offset, .size, .value_kind}` | **3,496** |
| `{.address_space, .offset, .size, .value_kind}` | **24** |

即全库 3,520 个参数中，**仅这 24 个** `global_buffer` 参数含 `.address_space`，实测值为字符串 `"global"`，原始字节 `A6 67 6C 6F 62 61 6C`。

- `.offset`：该参数在 kernarg 段内的字节偏移；
- `.size`：字节长度；
- `.value_kind`：参数类别字符串。

每个内核条目另带 `.kernarg_segment_size`（kernarg 段总长）。

### 1.4 组成恒等式：`kernarg = by_value + 66 + 190`

**31 个内核**（idx 0–25、29–33）实测满足：

```
.kernarg_segment_size = 用户 by_value 参数大小 + 66（13 个隐藏参数跨度）+ 190（未在 .args 中枚举的尾部）
```

该式对 31 个内核逐一成立。

**隐藏参数跨度 66 B 内含 16 字节空洞**（31 内核 × 8 目标取值集合 = {16}）：

| 相对偏移（相对隐藏区起点 = 该内核 `by_value` 大小 B） | 参数 | size |
|---|---|---|
| `+0x00` | `hidden_block_count_x` | 4 |
| `+0x04` | `hidden_block_count_y` | 4 |
| `+0x08` | `hidden_block_count_z` | 4 |
| `+0x0C` | `hidden_group_size_x` | 2 |
| `+0x0E` | `hidden_group_size_y` | 2 |
| `+0x10` | `hidden_group_size_z` | 2 |
| `+0x12` | `hidden_remainder_x` | 2 |
| `+0x14` | `hidden_remainder_y` | 2 |
| `+0x16` | `hidden_remainder_z` | 2 |
| **`+0x18`–`+0x28`** | **空洞（16 B，无对应 `.args` 条目）** | **16** |
| `+0x28` | `hidden_global_offset_x` | 8 |
| `+0x30` | `hidden_global_offset_y` | 8 |
| `+0x38` | `hidden_global_offset_z` | 8 |
| `+0x40` | `hidden_grid_dims` | 2 |

13 个隐藏参数 size 合计 = 4+4+4+2+2+2+2+2+2+8+8+8+2 = **50 B**；加 **16 B 空洞** = **66 B**。

**实际拼接式**：

```
Σ(参数 size) + 206 = kernarg      （206 = 50 隐藏 size + 16 空洞 + 190 尾部）
⇔ Σsize = by_value + 50，kernarg = Σsize + 206
```

对 31 个内核逐一成立。

**按表拼 kernarg 的正确做法**：用户参数放 `by_value`（offset 0，长度 = 表内 `size/by_value`），其后按上表**绝对偏移**放置 13 个隐藏参数，写入时将 `+0x18`–`+0x28` 的 16 B 与尾部 190 B 一并保留（31 内核情形）。

### 1.6 结构自检三项（8 目标 × 34 内核全量）

| 检查 | 结论 | 量化证据 |

## 4. 跨目标一致性结论汇总

### 4.1 参数面（一致）

| 项 | 结果 |

### 4.2 资源面（8 个字段不一致）

16 个字段实体中：

- **8 个 8 目标全一致**：`.kernarg_segment_size`、`.kernarg_segment_align`、`.max_flat_workgroup_size`、`.uniform_work_group_size`、`.uses_dynamic_stack`、`.language`、`.language_version`、`.symbol`；

### 4.3 三条必须随引用给出的限定

1. **参数面的一致不等于资源面的一致**（§4.1 的限定）。
2. **`.wavefront_size` 32 / 64 的差异在目标轴上，不在内核轴上** —— 32 为 `#1`–`#7`（238 条）、64 为 `#8`（34 条）。
3. **`#8 gfx9-generic` 是系统性离群目标**：
   - `.wavefront_size` = 64（独有）；
   - `priv` 两个唯一极值（404 / 84）均只在 `#8` 出现；
   - `.workgroup_processor_mode` **整体缺席**（`#8` 为 17 键）；
   - `group` = 20480 的内核（k5）在 `#1` / `#8` 与 `#2`–`#7` 分属两档。

   ⇒ **以单一目标取参数会系统性出错。**
