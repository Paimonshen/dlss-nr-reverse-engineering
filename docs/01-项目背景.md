# 项目背景

## 1. 这个项目是什么

本项目是对 **DLSS NR（Neural Rendering，神经渲染降噪）** 模块所做的一次逆向工程与可行性研究。

研究的直接对象是一个 **AMD 侧的 DLSS-NR 运行时模块**：

| 项 | 值 |
|---|---|
| 文件名 | `dlssnr_amd_pass1.dll` |
| 大小 | 7,156,224 字节（`0x6D3200`） |
| SHA256 | `3C9CA13F0F5FC36A690BA424C457003BCFCC1080B4B785974CDD7E9AE2BC1DD8` |
| 格式 | PE32+，ImageBase `0x180000000`，共 12 个节 |
| 模块身份 | 模块名（导出目录 Name RVA 指向）为 `version.dll`，即以 `version.dll` 为名的**代理 DLL** |
| 源码可得性 | 原始 device 侧源码**不在工作区内**（详见下节） |

该 DLL 的 device 侧代码被封装在 `.hip_fat` 节内，是 8 个 AMDGPU device bundle，运行在 **AMD HIP** 运行时（`amdgcn-amd-amdhsa` 体系）之上，通过 `amdhip64_7.dll` 这一 HIP 运行时接口完成设备枚举、内存分配与内核启动。

## 2. 为什么要做这件事

项目的目标是回答一个具体的工程问题：

> **这个 DLSS NR 模块能否被重编 / 移植，从而在 Intel Arc（Xe / XMX）硬件上运行？**

这里的「重编 / 移植」不是指「让 AMD 的二进制在 Intel 上直接跑」——这不是一个可行目标，而是指评估**把该模块的计算内核按 Intel 侧的执行模型重新实现**所需面对的全部结构性条件：

- 34 个设备内核各自的参数布局与资源需求是什么？
- 这些内核的算子语义是什么，能够映射到哪一类 Intel 侧原语？
- host 侧的运行时接口要替换多少、替换成什么？
- 147 MB 的权重数据是什么格式，需要怎样的转换？
- 有哪些问题在当前条件下根本无法回答？

因此本项目的定位是 **互操作性研究（interoperability research）**：产出的是**可回溯的规格与评估**，而不是一个可直接运行的移植版。

### 2.1 硬件目标

| 项 | 值 |
|---|---|
| 目标平台 | Intel Arc B580（Xe2 / Battlemage 架构，含 XMX 矩阵引擎） |
| 源平台 | AMD HIP / `amdgcn-amd-amdhsa`（8 个 device target） |
| 目标运行模型 | SYCL / oneAPI Level Zero（含 XMX 路径与通用 SPIR-V 路径两种候选） |

### 2.2 环境约束（三条硬约束，直接决定结论的边界）

| # | 约束 | 后果 |
|---|---|---|
| **E-1** | **无 AMD 硬件** | 任何「运行期验证」类工作不可执行：既不能在 AMD 上跑原版，也不能取得原版的运行期行为（如 block 调度、符号写点） |
| **E-2** | **无 AMDGPU 反汇编工具** | `llvm-objdump` 在工作区内检索命中 0；`capstone` 5.0.7 不支持 AMDGPU。34 个内核的 `.text` 合计 **6,081,960 字节**（8 个 device ELF 之和），**被反汇编的指令数 = 0** |
| **E-3** | **无 Intel / SYCL / HIP 编译工具链** | `icx` / `icpx` / `dpcpp` / `clang` / `cl` / `hipcc` / `g++` 的 `Get-Command` **各命中 0**；未能编译工作区内的任何 `.sycl` / `.hip` 源文件 |

这三条约束意味着：**本项目的所有结论，其验证上限是「静态字节级」**。凡属运行期、指令级、编译级的判断，本项目一律标注为「需外部条件」或「需外部资料」，不给结论。

## 3. 分析对象的可得面貌

### 3.1 device 侧：8 个 AMDGPU bundle，无任何 Intel / Xe / SPIR-V 目标

`.hip_fat` 节内的 `__CLANG_OFFLOAD_BUNDLE__` 容器共 9 条 bundle 条目：

- **1 条 host 占位**（entry `#0`，triple `host-x86_64-unknown-linux-gnu-`，**size = 0**，是空区间占位）；
- **8 条 device bundle**，triple 全部为 `hipv4-amdgcn-amd-amdhsa--<target>`。

8 个 device target 依次为：

| 编号 | triple |
|---|---|
| `#1` | `hipv4-amdgcn-amd-amdhsa--gfx10-3-generic` |
| `#2` | `hipv4-amdgcn-amd-amdhsa--gfx11-generic` |
| `#3` | `hipv4-amdgcn-amd-amdhsa--gfx1100` |
| `#4` | `hipv4-amdgcn-amd-amdhsa--gfx1101` |
| `#5` | `hipv4-amdgcn-amd-amdhsa--gfx1102` |
| `#6` | `hipv4-amdgcn-amd-amdhsa--gfx1200` |
| `#7` | `hipv4-amdgcn-amd-amdhsa--gfx1201` |
| `#8` | `hipv4-amdgcn-amd-amdhsa--gfx9-generic` |

**该 fat binary 内不存在任何 Intel / Xe / SPIR-V 目标**：9 条 triple 的全体集合中无 `spirv`、无 `intel`、无 `xe` 字样的体系标识。

8 条 device ELF 的 `e_machine = 0xE0`（224 = **EM_AMDGPU**）8/8 命中；`e_ident` 均含 `EI_OSABI = 0x40`（ELFOSABI_AMDGPU_HSA）与 `EI_ABIVERSION = 4`，与 `hipv4-` 前缀自洽。

### 3.2 内核与参数元数据

每个 device bundle 的 `.note` 节内承载 `NT_AMDGPU_METADATA` 类型的 msgpack 元数据文档，其中包含：

- **34 个内核**的完整参数规格（`.args` 逐参数 `.offset` / `.size` / `.value_kind`，以及 `.kernarg_segment_size`）；
- **16 个资源字段**（`.group_segment_fixed_size`、`.private_segment_fixed_size`、`.sgpr_count`、`.vgpr_count`、spill 计数、`.wavefront_size`、`.max_flat_workgroup_size`、`.workgroup_processor_mode` 等）。

8 目标 × 34 内核 = **272 个内核条目**，每个目标 **440 个参数**（合计 3,520 个参数条目）。

### 3.3 host 侧

- 17 个导出，全部是 `FF 25` 跳转桩（VERSION.dll API 名）；
- **194 条导入**，分布在 10 个 DLL 上，其中 **`amdhip64_7.dll` 占 29 条**（HIP 运行时 API）；
- 两条 8 字节步长的函数指针表（wrapper 注册表）；
- 34 处 `__hipRegisterFunction` 注册调用，与 272 ÷ 8 = 34 个内核一一对应。

### 3.4 权重

147 MB 量级的权重实体是**外部文件**（非 DLL 内嵌）：

| 项 | 值 |
|---|---|
| 大小 | 147,689,451 字节（`0x8CD8FEB`） |
| SHA256 | `6BF8DC931EF3CCFFE18C82DE26AB374156E7F19539FFCF8EABAA25DCA5CF15AB` |
| 首 8 字节 | `44 4C 53 53 4E 52 57 31` = ASCII `DLSSNRW1` |

该容器格式在本项目内**已被完整解出**（见 `05-Intel可行性评估.md` 第 6 章与 `06-未解缺口与限制.md`）。

## 4. 工作区内是否存在「源码」

这是评估工作必须首先回答的问题，因为答案直接决定后续所有工作的可用材料。结论是：**部分存在，但不是该 DLL 的源码。**

工作区内确有一棵自研的 pass 侧工程树（`Engine/`，28 个文件），其中包含：

- Swin 注意力算法的**再实现**（含 `SwinParams` 结构、`windowSize` / `shiftSize` 循环移位、`relPosBias` 相对位置偏置及其在 score 计算中的使用点、online softmax）；
- block 调度的**再实现**（`NUM_BLOCKS = 71`、`BlockConfig`、分段常量、`GetNumLayers()`）；
- Intel 侧的 SYCL 尝试（含 `joint_matrix` 的 GEMM 模板）；
- 权重解析器。

但这棵树**与 DLL 不同构**，对撞证据如下：

| # | 依据 | 证据 |
|---|---|---|
| N1 | **内核基名对撞 2/30** | `Engine/` 去重基名 6 个；DLL 34 内核去重基名 **30** 个；**交集仅 2 个**（`k_swin_1h_32_fp8`、`k_swin_var`）⇒ **28/30 个 DLL 基名在该树中不存在** |
| N2 | **该树有而 DLL 无的 4 个基名** | `blend_output` / `dlssnr_imgenc` / `mlp_projection` / `residual_add` —— DLL 34 内核中不存在这四个名字 |
| N3 | **34 内核名在该树之外零命中** | 全工作区 2,996 个非 `Engine/` 源文件中，10 个具名基名**各 0 命中** |
| N4 | **Git 全历史亦无等价物** | 历史源文件路径 5,951 个，路径子串 `engine/` **0**、`swin` **0**、`runtime_intel` **0**；`Engine/` 在工作区为 **untracked** |
| N5 | **依赖的 AMD SDK 不在工作区** | `hip/hip_runtime.h` 本体 **0 命中**；`rocm` 目录 **0**；`hipcc` **0**；`*.a` / `*.so` **0** |

⇒ **两侧是同一网络的两个不同实现**：`Engine/` 是同网络的**再实现工程**，**不是**该 DLL 的源码。

**一处必须沿用的更正**：DLL 的 12 个节中**不含 `.rsrc`**；147 MB 量级的实体是**外部包权重文件**，与 DLL 内的打包区（`.hip_fat` 6,649,000 字节）**分开计量**。

## 5. 分析内容概览

本项目完成的分析工作可归为五个面：

### 5.1 容器与格式层

- PE 结构逐字段解析（12 节节表、导出表、导入表、`.reloc`、`.data` 文件映像边界）；
- `__CLANG_OFFLOAD_BUNDLE__` 头部解析与 9 条 bundle 条目的完整性校验；
- 8 个 device ELF 的节表、符号表、`.kd` 描述符解析；
- md-snapshot `.note` 节内 AMDGPU msgpack 元数据的解码。

### 5.2 参数与资源规格层

- 34 个内核的逐参数布局（`offset` / `size` / `value_kind`）与 `kernarg_segment_size`；
- 16 个资源字段的取值集合、频次与跨 8 目标的逐格一致性；
- 组成恒等式（`kernarg = by_value + 66 + 190`）与三个例外内核。

### 5.3 host 侧结构层

- `version.dll` 代理导出面（17 项 `FF 25` 桩）；
- 194 条导入面逐 DLL 分类；
- `hipLaunchKernel` thunk 阶梯与 IAT 槽的逐条映射；
- 两张 8 字节步长函数指针表（表 A / 表 B）的全槽位语义；
- kernel 注册机制（34 处注册调用与表槽位的配对）。

### 5.4 算子与权重层

- 34 个内核的算子类型推定与结构特征；
- 权重容器逐字节解出（头部、153 条索引条目、载荷区、三条恒等式）。

### 5.5 可行性评估层

- 内核 A / B / C 三分类（资源面与参数面是否需改写）；
- 资源适配（SLM / 私有段 / 波前 / 工作组）；
- host 侧导入面替换面（29 / 194 条）；
- S0–S7 路线图与 23 个可验证里程碑；
- 未闭合缺口与外部资料清单。

## 7. 阅读约定

### 7.1 证据强度分级

本文档集对每条结论标明其证据层级。读者在引用时须一并给出层级：

| 标记 | 含义 |
|---|---|
| **已证** | 有原始字节、PE / ELF 结构或可复算算术作为判据 |
| **倾向** | 有抽样证据指向某一解释，但未做全量检验，**不升级为已证** |
| **需外部资料** | 判定依赖工作区之外的文档或规范，**本项目不给结论**，只给待查方向 |
| **未解** | 在工作区范围内无判据可以裁定 |

### 7.2 口径纪律

若干处数值存在**多个口径**，引用时须写明取自哪一个，否则会产生错误结论。已登记的口径对包括：

- **272 条目口径**（34 内核 × 8 目标）与 **34 内核口径**（单目标计）；
- **跨目标不一致性的三个计数口径**（字段×内核对 **163** / 与 `#1` 比格数 **605** / 8 目标两两比格数 **2183**）—— 三者不可混用，「163 × 7」或「163 × 28」的估算都是错的；
- **取值 + 出现次数口径**与**单点归属口径**（如 64,640 B 出现 8 次，不得写成「某内核 = 64,640」而不附口径）；
- **spill 字段的非零条目数口径**与**取值种数口径**。

### 7.3 术语

- **kernel / 内核**：GPU 设备侧的可执行函数，本项目中特指 `.hip_fat` 元数据内的 34 个内核。
- **bundle / bundle 条目**：`__CLANG_OFFLOAD_BUNDLE__` 容器内的一条目标条目。
- **kernarg**：kernel 参数段。
- **wrapper**：host 侧包裹一个内核启动流程的薄函数。
- **handle 表**：即两张 8 字节步长函数指针表，承载 wrapper 地址。
- **block**：网络结构的块（共 71 个），与内核之间是多对一的关系。
