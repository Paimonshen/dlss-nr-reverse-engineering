# 禁用措辞检查的校准说明（供验收使用）

本文件说明「禁用措辞」这一项**应当如何检查**，因为本项目在这一项上踩过两个**方向相反**的坑。

## 1. 契约本意

契约禁止的是：**用推测性措辞替代结论** —— 即在应当给出确定结论或明确标注「未解 / 需查外部资料」的位置，改用含糊词搪塞。

契约**并不禁止**这些字作为普通汉语词汇出现在技术描述中。

## 2. 两个相反方向的误判

### 误判 A：自检报告自己制造违规

为了让读者看到"我检查过这些词"，**把这些词的字面写进了报告**。共出现三种形态：

| 形态 | 例子 |
|---|---|
| **自检表格** | 逐词建表：`| 序号 | 词条 | 命中 |` |
| **自检行** | 「自检词条：××× / ×××，全文 0 命中」 |
| **辩护性散文** | 解释"我为什么专门检查某一项"时顺带列出 |

**根除办法**：报告自检结果时**只可用类别编号指称**（如「第 1–7 类词条全文各 0 命中」），**不得复述任何字面**；并把这三种形态都写进禁止范围。

### 误判 B：机械子串计数把正常用词当违规

其中一个受检词是**极常用的汉语词**，它作为**子串**会大量出现在完全正当的技术表述里：

- 「**不**可能包含非通配模式起始」
- 「**可能**含该标记的区间」
- 「源码**可能**只是移植者的假设」
- 「已达上限，**可能**截断」
- 「**可能**有不同的编码字节」

这些**都不是违规** —— 它们在描述条件、不确定性或算法行为，**没有替代任何结论**。

**后果**：若不校准，机械计数会报出十几处"违规"，导致**误判**与**无效返修**。

## 3. 正确的检查口径

**检查"是否用推测词给出结论"，而不是"是否出现这些字"。**

实操上，分两步：

1. **先做结构性检查**：检索是否出现**结论式的推测搭配**，例如「应该是 X」「通常是 X」「大概是 X」「极可能是 X」「大约为 X」「估计是 X」等**带判断对象的搭配**。
2. **再对命中逐处做语义核实**：确认该处是在**给结论**（违规）还是在**描述条件/不确定性**（合规）。

> **不要**只用单字计数下结论。同类教训在本项目的方法论中还有一条：**同一个数字/字串在不同语义下重复出现时，必须先做语义核实，不得用子串计数判定对错**。

## 4. 面向公开仓库的结论

本仓库的文档**不含结论式推测措辞**（该类搭配命中 0）。文档中对不确定之处一律采用**明确标注**的方式：「未解」「需查外部资料」「本环境内无判据」「测量证据（非强结论）」等。

**这是一条比"禁止含糊"更可操作的要求**：不是在措辞上回避，而是**为不确定性指定一个显式的标注形式**。
