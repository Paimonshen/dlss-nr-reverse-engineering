# 质量门禁与验收链

本项目对"结论可信"的要求高于"结论完整"。为此设置了**多层独立门禁**，并把门禁的失败视为可接受、可预期的正常态。

## 1. 门禁层

```
产出方（逆向/综合）
      ↓  交付物落盘
独立验证门（自建解析链、独立重算、可推翻）
      ↓  通过 / 需返修（findings）
返修门（定点更正，保留原文 + 修订记录）
      ↓
复验门（round 2，只验返修面，不重跑已通过的全量复算）
      ↓
独立验收门（抽样核查 + 禁止内容清单逐条核对）
      ↓  ACCEPT / needs_revision
结项
```

**要点**：**返修与复验是常态，不是失败**。本研究的主交付物经过**多轮返修 + 复验**才 ACCEPT。每一轮都留下修订记录（位置 / 改动前原文 / 改动后文本 / 依据）。

## 2. 验收判定的两级结论

验收只给两种结论，**必须写明理由**：

| 结论 | 含义 | 典型理由 |
|---|---|---|
| **ACCEPT** | 内容零失真，且引用链可复现 | 抽样全部独立复算通过 |
| **needs_revision** | 不满足上条，但**不构成内容崩塌** | 例如：输入基线失效（哈希未同步）、计数穷尽性不足、遗漏登记某能力边界 |

**并且要求明确写出"为什么不是另一种结论"**，例如：为何是 needs_revision 而不是 reject（因为**内容零失真**），为何不是 ACCEPT（因为**基线不可复现**）。

## 3. 抽样核查的强制项

验收方必须做**指定抽样**，且量不得低于下限，例如：

- **内核分类**：抽 ≥5 个内核，逐条从元数据独立复算其分类依据；
- **算子映射**：抽 ≥3 条，判定其是否**只给待查方向而未给能力结论**；
- **导入面替换**：抽 ≥5 条，独立复算替换目标；
- **来源标注合规**：抽 ≥10 条，判定每条标注是"已确认材料"还是"外部知识（须标需查外部资料）"；
- **越界改动**：抽 ≥3 处**未被更正清单点名**的位置，确认未被误改。

**并且要求：抽样不足下限即为验收不通过**（不接受"抽了代表性几条"）。

## 4. 禁止内容清单（验收的必查项）

对面向公开的产物，验收方必须**逐条核对**（不得抽样）以下禁用内容：

| 类别 | 检查方式 |
|---|---|
| 受版权保护的第三方二进制（如 NVIDIA 原版） | 全文 + 文件清单检索 |
| 凭证（key / token / 密码 / 私钥） | 文件类型 + 内容检索 |
| 含用户名的绝对路径 | 字符串检索 |
| 内部工作目录与临时产物 | 路径检索 |
| 禁用措辞（一组预先列举的推测性词条） | 逐类命中计数 |

> **关于禁用措辞的自检**：本项目在这一项上反复踩到同一个陷阱 —— **为了证明"没有使用这些词"，就把这些词写在自检报告里**，从而自己制造了违规。共有**三种形态**都出现过：**自检表格**（逐词建表）、**自检行**（"词条：…，命中 0"）、**辩护性散文**（解释"我为什么专门检查某项"时顺带列出）。
> **根治办法**：在要求里明确「报告自检结果时**只可用类别编号指称**（如"第 1–7 类词条全文各 0 命中"），**不得复述任何字面**」，并把这三种形态都写进禁止范围。

## 5. 数字与措辞的纪律

这些纪律来自本项目实际发生的错误，全部写入了流程：

1. **区间类判据**：端点必须**先独立确定**，不得沿用先前假设的边界。
2. **计数被更正后必须做全文传播自查**（范围 + 模式 + 命中数）。
3. **凡「不存在 X」的断言，必须在更宽范围内二次检索**（一次范围不足的"不存在"就是一次假否定）。
4. **凡「源码常量 vs 数据文件实测」冲突，以数据文件为准**（源码可能只是移植者的假设）。
5. **凡「跨域锚点」类表述，必须两侧都给命中数**（只看一侧就宣称对应，是错的）。
6. **凡「冲突项计数」必须给「预测规则 + 逐项明细 + 冲突项总数」三者**（只举例数项会漏项）。
7. **凡「同一数字」在不同语义下重复出现，必须先做语义核实，不得用子串计数判定对错**。
8. **凡「表内每行合格」不得推出「表的条数等于母集」** —— "逐项核"与"穷尽核"是**两个独立动作**。
9. **凡「基准版本」不得等同于「实测版本」** —— 复验第一步必须是**重新取指纹并核对是否仍是被验的那一版**。
10. **任何改动完成后必须重新取指纹复核**，不得假定"我改对了"；修一个矛盾时要检查**是否引入了同类矛盾**。
11. **上游文件变更后，已落盘的下游文档必须刷新基线**（否则出现"基线漂移"：引用了后来被改的版本）。
12. **面向成员的更正必须逐句标明主语**，两个主语不同的事实不得并置，否则会抹掉某次自曝更正的价值与轨迹。

## 6. 交付物的指纹约定

- 对**文本交付物**：给出**原始文件哈希**（字节数 / 行数 / 十六进制 SHA256）。
- 对**自指涉文档**（文末载有自身哈希）：原始哈希**不能内载于文件自身**（写入即改变该值）。此时内载**"规范化自指哈希"**（把指纹行替换为定长占位后再取 SHA256），而**引用一律以现场实测的原始哈希为准**。
- **不要引用**文档末行的"自报字节数/行数"这类自照值 —— 它可能与磁盘实际不符。
